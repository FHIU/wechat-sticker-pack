# 自建 / 私有 Agent 接入清单

适用于你有自己的 Agent 运行时（自研、Coze/扣子、Dify、字节方舟、或某个内部平台），能调模型、能跑代码节点、能自己做交互。

本仓库的内容**不需要改**，要做的是三处「接线」。

---

## 接线一：生图调用（必须，否则流程断在 S3）

`SKILL.md` 只写「生成 1 张母图」，不绑定任何模型。你的 Agent 需要提供图像生成工具，并保证：

| 要求 | 原因 |
|---|---|
| 支持 `1024×1024`、纯白背景 | 抠图算法按白底阈值工作，暗底图会失效 |
| 只画角色，不画文字 | 中文一律排版层叠加 |
| 同一角色可复用参考图（垫图 / image reference） | 逐张要保持同一张脸，纯文本描述做不到 |
| 返回本地文件路径或可下载 URL | 后续脚本要读文件 |

Coze / Dify 里直接用「图像生成」节点；自研环境接你的模型 API。节点命名建议 `generate_image`，入参 `prompt`（必填）、`reference_image`（可选）。

## 接线二：确认机制（必须，否则五关卡形同虚设）

五关卡的「停住问」需要宿主能**真正暂停**并等用户回答，不是把问题写进回复继续往下跑。三种实现：

1. **工作流暂停节点** — Coze/Dify 的「问答」或「等待输入」节点，出口按回答分支
2. **状态机** — 自研环境给会话存 `stage` 字段，取值为 `S0/S1/S4/S5/S7`，未流转就不允许调生图工具
3. **工具级硬拦** — 在 `generate_image` 前加守卫：`stage` 不在白名单直接抛错

第 3 种最省事也最有效：模型想跳过时会被工具本身拦住。

```
允许出母图的 stage: S1 已通过
允许出总览图的 stage: S4 已通过 且 名称清单已确认
允许批量出图的 stage: S7 已通过
```

## 接线三：脚本执行通道

五个脚本是标准 CLI，你的环境只要能执行 `python3` 即可。建议封装成一个工具：

```json
{
  "name": "run_sticker_script",
  "description": "执行表情包处理脚本",
  "parameters": {
    "script": { "enum": ["cutout", "compose", "assets", "mark", "validate"] },
    "args": { "type": "array", "items": { "type": "string" } }
  }
}
```

不要暴露成「执行任意 shell」，只白名单这五个脚本。

依赖：`pip install -r requirements.txt`（Pillow / numpy / opencv-python-headless）。云端沙箱若装不了 opencv，`assets.py` 与 `mark.py` 仍可单独用。

## 可选：把提示词版本号带进系统提示

如果你的 Agent 会在不同版本间切换，在系统提示尾部加一行：

```
表情包技能版本：wechat-sticker-pack v1.2.0
```

便于排查「为什么这次没走关卡」。

## 最小自检（接完跑一遍）

1. 说「做一套表情包」→ 它应该只问 S0，**不生成任何图**
2. 答完 S0 → 问 S1，仍不出图
3. 答完 S1 → 出提示词文稿，然后出 1 张母图，停下
4. 说「不行，重来」→ 只改母图，不该跳到总览图
5. 母图通过 → 逐张问名称，问满 N 次，一次一张

五步都过，接线就算对了。任一步跳过，回去看接线二。
